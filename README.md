# mitm-core

**A TypeScript-based, extensible Man-in-the-Middle (MITM) proxy framework for Node.js.**

`mitm-core` provides a typed plugin system and phased processing pipeline for intercepting, inspecting, and modifying network traffic. It enables developers to build custom proxy behavior, network debugging tools, and traffic analysis applications.

## Prerequisites

`mitm-core` intercepts HTTPS traffic by generating leaf certificates for target hosts and signing them with a Root Certificate Authority (CA). Before starting the proxy with HTTPS interception enabled, you must provide a CA certificate and its corresponding private key.

### Root CA Setup

Place your Root CA credentials in the `creds/__self__/` directory at the root of your project.

Expected directory structure:

```text
your-project/
├── creds/
│   └── __self__/
│       ├── CA.pem
│       └── key.pem
├── package.json
└── index.js
```

- `CA.pem` — The Root CA certificate.
- `key.pem` — The corresponding private key.

### Generate a Root CA

You can generate a local Root CA using OpenSSL.

Create the required directory and move into it:

```bash
mkdir -p creds/__self__
cd creds/__self__
```

Generate a 2048-bit private key:

```bash
openssl genrsa -out key.pem 2048
```

Generate a self-signed Root CA certificate valid for 10 years:

```bash
openssl req -x509 -new -nodes \
  -key key.pem \
  -sha256 \
  -days 3650 \
  -out CA.pem
```

When prompted, provide the certificate details. Set the **Common Name** to a recognizable name, such as `mitm-core-root`.

### Protect Your CA Credentials

Keep `key.pem` private. Do not commit your CA private key to version control or distribute it to untrusted parties.

If you use a local CA for development, only install and trust its certificate on systems you own or are authorized to administer.

### Configure Certificate Trust

Clients must trust the Root CA certificate to accept certificates generated by the proxy without certificate-validation errors. Configure trust only in the test environment or on devices you are authorized to manage.

For usage instructions and a working proxy setup, see the [Quick Start Guide](https://mitm-core.debanshupanigrahi.dev/getting-started).

## Installation

Install `mitm-core` from npm:

```bash
npm install mitm-core
```

Import the required APIs into your project:

```ts
import { Proxy, BasePlugin } from "mitm-core";
```

For setup instructions and a working proxy example, see the [Configuration Guide](https://mitm-core.debanshupanigrahi.dev/configuration).

## Features

- **HTTP/1.1 Interception** — Intercept and process plain HTTP requests and responses.
- **HTTPS Interception** — Decrypt HTTPS traffic through TLS interception using dynamically generated certificates.
- **WebSocket Support** — Intercept and modify WebSocket (`ws://`) and secure WebSocket (`wss://`) messages.
- **Typed Plugin System** — Extend proxy behavior with custom plugins, typed event payloads, and lifecycle hooks.
- **Phased Processing Pipeline** — Process traffic through organized pipeline phases with controlled execution and abort handling.
- **Rule Engine** — Define custom, file-backed rules for matching targets and controlling proxy behavior.
- **Plugin Development** — Build custom plugins using `BasePlugin`, typed event payloads, and lifecycle hooks to extend proxy behavior and implement custom traffic-handling logic.
- **Certificate Caching** — Cache generated TLS certificates to reduce repeated certificate-generation work.
- **Response Caching** — Optionally cache eligible upstream responses.
- **Asynchronous Plugin Execution** — Support synchronous and asynchronous plugin handlers with configurable execution timeouts.
- **Streaming Responses** — Forward large request and response bodies through streaming pipelines.
- **Connection Lifecycle Management** — Handle proxy startup, shutdown, connection errors, and socket cleanup.
- **TypeScript-First API** — Provide typed interfaces and event maps for better IDE support and compile-time checking.

Only intercept traffic on systems and networks you own or have explicit permission to test. You are responsible for complying with applicable laws and protecting intercepted data. Keep your Root CA private key secure, and avoid installing or distributing CA certificates beyond environments you control.
